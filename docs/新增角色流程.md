# ARKTI 新增角色流程

本文档用于说明在当前仓库中新增一个角色时，需要改哪些文件、按什么顺序改、改完后如何自查。

## 1. 先理解角色在项目里的落点

当前项目里，一个“角色”并不是只存在于一个文件中，而是由下面几部分共同组成：

- `src/data/archetypes.json`
  八个二次元原型的定义（名称、叙事文案、**基准六维向量**等）。新增角色时必须选用其一作为 `archetypeId`；若使用 `signature.uniqueAxes` 做轴上微调，仓库提供的 `vectors:sync` 会以这里的向量为底稿合并。
- `src/data/characters.json`
  角色的核心资料，包含角色代码、标题、匹配 MBTI、原型、标签、解析文案、六维向量、`signature` 等。
- `src/data/characterVisuals.json`
  角色视觉配置，包含结果页实际使用的立绘路径、主题色，以及可选的小人动画、背景立绘与裁切参数。
- `public/images/characters/`
  角色立绘图片资源。角色必须有主立绘，且应为透明背景素材。
- `public/images/small_characters/`、`public/images/background/`（可选）
  结果页增强展示用：小人循环动画（`.webm`）、全屏/大卡背景图等；不配则依赖代码中的回退逻辑。
- `src/data/characterProbabilities.json`
  角色命中概率配置（含模拟用的 `seed`、`runs` 元数据），用于结果页展示“人群命中率”。
- `src/i18n/characters.ts`
  角色名和作品名的多语言映射表，用于国际化展示。

类型定义以 `src/types/quiz.ts` 中的 `CharacterMatch`、`ArchetypeId` 为准，新增字段前请先对照类型，避免 JSON 与 TypeScript 不一致。

运行时的关系如下：

1. `quizEngine.ts` 根据答题结果对 `characters.json` 中的角色进行排序（结合 MBTI、原型得分、向量相似度与 `signature`）。
2. `characterVisuals.ts` 用 `characterVisuals.json` 中的配置补全立绘、主题色、背景等展示信息。
3. `characterProbability.ts` 从 `characterProbabilities.json` 读取该角色的命中率。
4. `src/i18n/characters.ts` 为角色名和作品名提供 `zh-CN`、`zh-TW`、`en`、`ja` 的展示文本。

所以，新增角色至少要保证“原型选型、资料、视觉、素材、概率、i18n”能对上同一个 `id`；若使用向量同步脚本，还需保证 `archetypeId` 与 `signature.uniqueAxes` 合理。

同时，本项目对新增角色还有以下硬性要求：

- 角色必须配套主立绘，且图片必须处理成透明图层。
- 每次新增角色后，都必须基于最新角色库全局重跑一次稀有度（命中概率）数据，不能只手动补一个值。
- 多语言映射需补齐，避免非简中环境展示异常。

## 2. 新增角色的标准流程

推荐按下面顺序操作，避免中途出现引用断裂。

### 步骤 1：先确定角色基础方案

在落文件前，先把下面这些内容定下来：

- `id`
  全仓库唯一，建议使用英文小写加连字符，例如 `kaname-madoka`。
- `name`
  角色展示名（简中默认；多语言仍以 `characters.ts` 为准）。
- `series`
  作品名。
- `code`
  对外展示的角色自定义代码，这是结果页核心标签。
- `matchCode`
  角色的底层 MBTI 映射，例如 `INFP`。计分仅使用该四字母，不再支持多类型弹性。
- `archetypeId`
  必须是现有 8 个原型之一（与 `archetypes.json` / `src/types/quiz.ts` 中 `ArchetypeId` 一致）。
- `vector` 与 `signature.uniqueAxes`
  六维向量：`expression`、`temperature`、`judgement`、`order`、`agency`、`aura`。详见下文「六维向量怎么维护」。
- `tags`、`title`、`note`
  结果页会直接展示，文案风格要符合当前项目的“严肃测试外壳 + 二次元角色解析”方向。

其中 `archetypeId` 目前只能从以下值里选：

- `luminous-lead`
- `icebound-observer`
- `oathbound-captain`
- `trickster-orbit`
- `gentle-healer`
- `shadow-strategist`
- `chaos-spark`
- `moonlit-guardian`

### 步骤 2：在 `characters.json` 新增角色主体

编辑 `src/data/characters.json`，新增一个对象。建议直接参考现有角色的结构，不要随意发明新字段。

最小结构如下（向量可先手写，也可在填好 `archetypeId` 与 `signature.uniqueAxes` 后运行 `npm run vectors:sync` 生成，见下一小节）：

```json
{
  "id": "new-character-id",
  "name": "角色名",
  "series": "作品名",
  "matchCode": "INFP",
  "code": "ABCD",
  "title": "结果页称号",
  "archetypeId": "moonlit-guardian",
  "tags": ["标签1", "标签2", "标签3", "标签4"],
  "note": "结果页角色解析文案。",
  "vector": {
    "expression": 0,
    "temperature": 2,
    "judgement": 1,
    "order": 0,
    "agency": 1,
    "aura": 2
  }
}
```

#### 六维向量怎么维护（两种方式，二选一或组合）

1. **手写完整 `vector`**
   直接填好六个轴，可与 `archetypes.json` 中同原型的基准向量对照微调。若同时使用 `signature.uniqueAxes`，语义上应是「在原型基础上的覆盖轴」；改完后可运行 `npm run vectors:sync` 校验与原型+uniqueAxes 合并后的结果是否一致（脚本会重写 `vector` 字段）。

2. **原型基准 + `signature.uniqueAxes` + 同步脚本（推荐与仓库现状一致）**
   - 在 `characters.json` 里设好 `archetypeId` 与 `signature.uniqueAxes`（只写需要偏离原型的轴）。
   - 执行：`npm run vectors:sync`（对应 `scripts/sync-character-vectors.mjs`）。
   - 脚本逻辑：先复制 `archetypes.json` 中该原型的 `vector`，再按 `uniqueAxes` 覆盖对应轴，与 `quizEngine` 中对 `uniqueAxes` 的理解一致。

可选增强字段：

- `image`
  可写在角色上，但当前项目最终展示优先取 `characterVisuals.json`，所以这里不是主入口。
- `signature.uniqueAxes`
  用于强调该角色在六维向量上相对原型基准的偏移（可与 `vectors:sync` 配合）。
- `signature.questionAffinity`
  用于把某些题目答案倾向额外绑定到该角色，提高辨识度。

`questionAffinity` 的格式示例（`expected` 取值见类型定义）：

```json
{
  "signature": {
    "questionAffinity": [
      { "questionId": "q12", "expected": "agree", "weight": 1.4 },
      { "questionId": "q20", "expected": "neutral", "weight": 1.2 }
    ]
  }
}
```

注意事项：

- `id` 必须唯一，并且后续所有文件都用同一个值。
- `matchCode` 必须符合 MBTI 四字母格式。
- `vector` 六个轴必须写全（手写或同步脚本生成均可）。
- `code` 不要和已有角色重复。
- `questionId` 必须能对应到 `src/data/questions.json` 中题目的 `id` 字段（例如 `q1`、`q2`…）。

### 步骤 3：补角色视觉配置

编辑 `src/data/characterVisuals.json`，为同一个 `id` 增加配置。至少需要主立绘与主题色，其余为可选增强：

```json
"new-character-id": {
  "image": "/images/characters/角色图片.png",
  "accent": "#7ec7f9",
  "smallCharacterVideo": "/images/small_characters/示例.webm",
  "backgroundImage": "/images/background/示例.png",
  "backgroundShadow": true,
  "backgroundPositionX": 0,
  "backgroundPositionY": 50,
  "imageScale": 1
}
```

这里的配置会被 `src/utils/characterVisuals.ts` 合并到最终结果对象中（`hydrateCharacterVisual`）。

注意事项：

- `image`、`accent` 为结果页最常用字段；`image` 必须指向 `public/` 下可访问的资源路径。
- `accent` 建议与角色视觉一致，结果页顶部色块、按钮和强调区会用到。
- `smallCharacterVideo`、`backgroundImage` 等可选；不配时仍有立绘与色值展示。
- 若仅接主立绘，至少保证 `image` + `accent` 与 `public/images/characters/` 中的文件一致。

### 步骤 4：放入角色图片（及可选素材）

把主立绘放到：

`public/images/characters/`

可选（与 `characterVisuals.json` 中字段对应）：

- `public/images/small_characters/` — 小人循环动画等
- `public/images/background/` — 大卡/全屏背景立绘

建议遵循当前仓库现状：

- 文件名尽量与角色中文名一致，便于人工管理。
- 主立绘必须使用透明背景的人物立绘。
- 构图尽量适配结果页头部大图展示，避免头部被裁切过多。

如果需要重新处理素材，仓库中已有相关脚本可参考：

- `scripts/remove_character_backgrounds.py`
- `scripts/process_character_assets.py`
- `scripts/generate_character_webp.py`

这里的要求不是“有图就行”，而是：

- 新角色必须有主立绘，不能留空。
- 图片必须先完成抠图，确保主体是透明图层，而不是白底或带杂色背景的整张图。
- 放进 `public/images/characters/` 的最终资源，必须和 `characterVisuals.json` 的路径完全对应。

如果原图不是透明背景，新增角色前应先完成抠图处理，再接入项目。

### 步骤 5：补充角色命中概率

新增角色后，不应只在 `src/data/characterProbabilities.json` 里手填一个值，而是要基于最新全量角色库重新生成整份稀有度数据。

推荐命令（与 `package.json` 中脚本一致）：

```bash
npm run prob:simulate
```

对应实现为 `scripts/probability-simulation.mjs`，会：

- 按固定 `seed`、大量随机答卷调用 `calculateQuizResult`，统计各角色成为「主推角色」的频率；
- 写回 `src/data/characterProbabilities.json`，并包含 `seed`、`runs`、`probabilities` 等元数据。

标准要求：

- 每次新增角色，都必须全局重跑一次稀有度。
- 重跑后，整体回写 `src/data/characterProbabilities.json`。
- 不建议只追加一条 `"new-character-id": x`，因为这会让整体分布失真。

**一致性提醒：** 模拟脚本中的「每次测验抽取题目数量」必须与 `src/constants/quizSession.ts` 里的 `QUIZ_SESSION_QUESTION_COUNT` 保持一致（当前为 20）。若将来修改其一，必须同步修改另一处，否则稀有度数据与真实答题流程不一致。

### 步骤 6：补齐 i18n 映射

编辑 `src/i18n/characters.ts`，至少补两类映射：

- `characterNameI18n`
  为新角色的 `id` 增加多语言名称。
- `seriesI18n`
  如果新角色来自一个之前未收录的新作品，也要为该作品补多语言名称。

角色名示例：

```ts
'new-character-id': {
  'zh-CN': '角色简中名',
  'zh-TW': '角色繁中名',
  en: 'Character English Name',
  ja: 'キャラクター名',
}
```

作品名示例：

```ts
'作品名': {
  'zh-CN': '作品名',
  'zh-TW': '作品繁中名',
  en: 'Series English Name',
  ja: '作品日本語名',
}
```

注意事项：

- 这一步不是可选项，新增角色默认需要做 i18n 适配。
- 如果只在 `characters.json` 里写中文名，而不补 `src/i18n/characters.ts`，英文、日文、繁中环境下会退回原始值，展示会不完整。
- 若角色所属作品是已有作品，只需复用已有 `seriesI18n` 项；若是新作品，必须新增该作品的多语言映射。
- `characterNameI18n` 的 key 必须与角色 `id` 完全一致。

首页等处的「当前角色数量」来自对 `characters.json` 的引用（如 `src/i18n/messages.ts`），一般**无需**再改单独清单；新增条目后计数会自动变化。

## 3. 新增角色时的判定建议

为了让新增角色在结果上“像这个角色”，而不是只挂一个名字，建议按下面逻辑补数据。

### 3.1 `matchCode` 怎么定

- 先定底层 MBTI。
- 这个值决定角色在大方向上的命中范围；匹配算法将 E/I、S/N、T/F、J/P 四轴分别计入总分（各 12.5%），见 `quizEngine.ts`。

### 3.2 `archetypeId` 怎么定

- `matchCode` 决定底层人格型。
- `archetypeId` 决定角色更接近哪一种二次元原型表现。
- 两者最好保持一致，不要出现明显互相冲突的设定。

可以直接参考 `src/utils/quizEngine.ts` 中 `TYPE_TO_ARCHETYPE` 的映射关系（MBTI → 原型），以及 `archetypes.json` 里各原型的叙事与基准向量。

### 3.3 `vector` 怎么定

`vector` 是角色细分排序的重要依据。当前六个轴为：

- `expression`：表达外放程度
- `temperature`：情感温度
- `judgement`：判断/决断倾向
- `order`：秩序与规划倾向
- `agency`：主动性与推动力
- `aura`：存在感与气场

建议做法：

- 先找 1 到 2 个仓库里最接近的已有角色作参照。
- 不要一上来把所有值都拉满。
- 真正有辨识度的地方，再通过 `signature.uniqueAxes` 或 `questionAffinity` 强化。
- 使用 `npm run vectors:sync` 时，以 `archetypes.json` 中对应原型的 `vector` 为起点，只改 `uniqueAxes` 里需要的轴。

### 3.4 `note` 和 `tags` 怎么写

虽然项目是二次元包装，但结果页文案不能只剩梗图。

建议保持这个平衡：

- `title` 负责记忆点和角色称号。
- `tags` 负责快速识别特征。
- `note` 负责把“人格倾向 + 角色观感”串起来。

不要把角色描述写成医学、诊断或心理治疗口吻。

## 4. 改完后的自查清单

至少检查下面这些点：

- `src/data/characters.json` 中新增角色的 JSON 结构合法。
- `id` 在所有文件中完全一致。
- `src/data/characterVisuals.json` 已补对应配置（至少 `image` + `accent`）。
- `public/images/characters/` 中确实存在对应主立绘。
- 图片已经完成抠图，背景为透明图层。
- 若使用 `uniqueAxes` + 同步脚本，已执行 `npm run vectors:sync` 且 `vector` 六轴齐全、数值合理。
- `src/data/characterProbabilities.json` 已基于 `npm run prob:simulate` 全量重算，且含与各角色一一对应的概率。
- `src/i18n/characters.ts` 已补角色名的多语言映射。
- 如果角色来自新作品，`src/i18n/characters.ts` 也已补作品名的多语言映射。
- `matchCode` 为合法 MBTI。
- `archetypeId` 为合法原型 ID。
- `vector` 六轴齐全。
- `questionAffinity` 引用的题号在 `questions.json` 中真实存在。
- 若修改了单次抽题数量，已核对 `quizSession.ts` 与 `probability-simulation.mjs` 一致。

### 可选：可达性粗测

如需观察新角色在随机答题下成为第一的频率分布，可运行：

```bash
node scripts/audit-reachability.mjs [迭代次数]
```

（默认迭代次数见脚本内参数；该脚本与正式「单次 20 题会话」的模拟口径不同，仅作辅助参考。）

## 5. 建议的验证流程

新增角色后，建议至少做一次最小验证：

```bash
npm run build
```

然后人工检查：

1. 启动本地站点，进入角色图鉴页或结果页。
2. 确认新增角色主立绘能正常显示，没有 404。
3. 确认图片已经是透明图层，没有白底、实底或明显抠图毛边。
4. 确认结果页主色、标题、标签、解析文案显示正常。
5. 切换至少一种非简中语言，确认角色名和作品名没有漏翻或退回异常值。
6. 如有调试入口或定向测试方式，检查该角色是否能被正常命中。

如果后续要做更稳的内容扩充，建议再补两类验证：

- 用固定 MBTI 样本检查该角色是否落在预期区间。
- 检查全局重跑后的稀有度分布是否合理，避免角色库扩充后命中率失真。

## 6. 一次典型新增的实际改动清单

一次完整的新增角色，通常会改这几处：

- `src/data/characters.json`
- `src/data/characterVisuals.json`
- `src/data/characterProbabilities.json`（通过模拟脚本生成）
- `src/i18n/characters.ts`
- `public/images/characters/…`（及按需的 `small_characters`、`background`）

常用 npm 脚本：

- `npm run vectors:sync` — 按原型与 `uniqueAxes` 回写 `vector`
- `npm run prob:simulate` — 重算 `characterProbabilities.json`

若还涉及素材处理或本地实验，可能还会使用：

- `scripts/process_character_assets.py`
- `scripts/remove_character_backgrounds.py`
- `scripts/generate_character_webp.py`
- `scripts/audit-reachability.mjs`（可选，粗测排名分布）

## 7. 最后原则

新增角色时，优先保证以下三件事：

- 角色代码对外展示明确。
- 底层 MBTI 与原型映射自洽。
- 文案、视觉、概率、素材四部分保持一致。

此外，下面三条应视为默认强约束：

- 没有透明抠图主立绘的角色，不算完整接入。
- 没有在新增后全局重跑稀有度的角色，也不算完整接入。
- 没有完成 i18n 适配的角色，也不算完整接入。

如果只补了名字和图片，没有补齐向量、原型、概率和结果文案，这个角色在当前项目里就还不算完整接入。
